App summary:       
Next generation AI tutor for students, with teacher-designed lesson plans executed by multimodal LLM. 
RAG-based with student progress tracking and adaptive teaching.
Generative UI using Turbo. 2-column layout, allowing the LLM to create visualizations, interactive elements, view media, work alongside the student, etc.
Likewise, the student can use the frame as a chalkboard to demonstrate understanding in visual ways beyond plain chat. 
Desktop-only to ensure appropriate interactivity and resource utilization. 
The goal is to match or exceed the tutoring ability of a talented and broadly knowledgeable 1-on-1 human tutor.

dev environment: ruby devcontainer
Intended app environment: containerized, run locally or in a secure environment, not internet accessible

frameworks/tooling:
- ruby on rails 7.2 (plan upgrade to 8)
- security: hosted locally only, up to user to make accessible to internet
- docker containerized + devcontainer
- tailwindcss + shoelace components                                                  
- interactivity - hotwire: turbo, stimulus
- DB: postgres
- Authentication: devise (upon Rails 8, could remove Devise and switch to the built-in generator and BYO)
- Authorization: User role: student / admin
- LLM servers - OpenAI, Anthropic; ollama (local) - translate openau api format to anthropic so can switch as needed
- LlamaIndex
- RAG: postgres + pgvector + neighbor gem
    https://github.com/ankane/neighbor - ruby gem to use pgvector with rails
    https://www.crunchydata.com/blog/ruby-on-rails-neighbor-gem-for-ai-embeddings
    https://medium.com/@rubyroidlabs/how-to-build-an-ai-chatbot-with-ruby-on-rails-and-chatgpt-9a48f292c37c

Features:
- Separate Teacher and Student interfaces/dashboards
- LLM co-design of lesson plans for teachers in bulk
- Student-progress-aware LLM tutor
- Multimodal tutoring: 
    - speech-to-text, text-to-speech
    - student can respond with either text/voice, or chalkboard sketching (rasterize and send as image to LLM)
    - large multipurpose chalkboard frame usable for handwriting, image viewing, generative UI components, iframe for websites, etc.
    - generative UI/mini-apps: GPT to stream components, send with turbo, render either in-chat or on chalkboard frame
    - automated lesson summary student progress reports

  t.references :student, foreign_key: { to_table: :users }

views
- system prompt editor - save system prompts in DB, admin can edit. prompts for lesson generation and tutor-bot
- course manager - list of lessons. include printable view. 
- resource archive: view prior used resources and planned resources
- lesson view (administrator) -  use LLM to generate a lesson plan in advance, then admin can edit it
- school view - lessons by subject
- lesson view - full screen optimized (16:9) -  description, tutor-bot chat. 
  > use lesson plan to conduct lesson. 
  > use streaming components to generate lesson tools on the fly within the chat. include iframe for web browsing. 
  > tutor-bot must have tool access to direct the iframe to relevant web pages from the lesson plans, eg. videos. 
  > use RAG to contemplate the student's previous strengths and weaknesses to tailor the lessons. 
- dashboard/progress view: show progress bars 


internal tools available to LLMs (give one-shot example in system prompts):
- update lesson view iframe url
- query student assessment history
- query lesson summary history
- save lesson summary, save student assessment


prompting principles
- prompt should include anti-screen-time: ensure lessons often include "escape from the computer" moments, suggesting real-world experiments, books, activities, learning outside, resource finding, etc., create hard stops in the lessons to help break up screen time 
- generally avoid testing/quizzing except in single questions as part of a lesson discussion. upon completion of each lesson, generate a summary of student's strengths and weaknesses demonstrated. add to DB. this collection must be embedded for RAG. 
- whenever a resource is used (web page, referenced literature, activity done, etc), add it to the DB archive of utilized resources. 
- Remember: the optimal solution for LLM recall may be full-text keyword search, vector search, a relational database, a graph database, or a mixture.
